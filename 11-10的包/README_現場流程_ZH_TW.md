# HoloGrip 第十一次現場包｜2026-11-10

## 跟第十次包的差別
- 模型：第 4～10 次資料重新訓練（27,132 下）。11/06 的 7 段訓練錄音全部進訓練，其中四鼓與歌曲3 右手手套斷線之後的音符不進訓練；兩次前測一律不進訓練。模型指紋 `831bc06d3afa…`。
- 自動錨點：與 `第十次的包_錨點` 相同。前 5 下姿勢集中、但兩條原規則都不成立時，只要每一下小鼓都在模型前 3 名，就以小鼓當錨點。
- 有線 COM 自動重開：11/06 右手手套三次停止送資料、COM 卻沒報錯，要重開程式才恢復。現在任一手超過 1 秒沒資料，程式會自己關掉再重開那個 COM（會讓手套重新開機），約 1～2 秒後資料回來，錄音不中斷；中間缺的那段照樣警告、寫進 manifest（`transport` 裡有 `reopens`、`silent_reopens`）。現場不用多做任何事。
- 無線：與 `第十次的包_無線` 相同。有線 COM 照舊可用，另有 `1W_`／`2W_` 無線啟動檔；錄製中任一手超過 0.5 秒沒資料會警告並寫進 manifest。
- 蒐集也能即時判斷：`2_蒐集這次`／`2W_` 錄製時，右側左右手卡片會顯示每一下判成哪顆鼓（分數）、最近 8 下、這段各鼓下數。用的是和 `1_測前次` 同一個模型與引擎，同一份資料逐下結果相同。
  - 只是顯示：Raw CSV 一筆不少、內容完全不變，訓練答案照樣來自 MIDI。
  - 判斷另存在 `Raw/即時判斷/<Raw 檔名>_即時判斷.csv`（放在子資料夾，對齊與標記程式不會把它當成 Raw）；manifest 多 `live_judge`（判斷下數、延遲、錨點）。
  - 程式開啟後約 5～10 秒載入模型，操作紀錄出現「即時判斷模型已載入」之後開始的錄音才會判斷；在那之前按開始，那段照樣錄 Raw，只是不顯示判斷。
  - 每次按開始都重新從頭校正（跟前測一樣，開頭先打幾下小鼓會更快穩定）。

## 現場操作（不變）
`00_CHECK.bat` → `1_測前次.bat`（連接雙手 → 鼓面歸零 → 開始新測試）→ `2_蒐集這次.bat` → `3_檢查這次MIDI.bat`。
- 每次都在小鼓鼓面上用同樣的姿勢歸零。
- 開始後先打幾下小鼓會更快校正；不打也可以。
- 如果中途移動鼓位：重新歸零，並重開一次測試。

## 11/10 收集建議
- 前測（盲測，不進訓練）：每隻手先打小鼓（左 10、右 10），再從小鼓開始每鼓左 20、右 20（小鼓、Hi-Hat、Crash、高音、中音、Ride、落地）。前測開頭一定要先打小鼓，自動錨點靠它。
- 記下這天是誰打；換人的話，左手各鼓位置可能和之前都不同。
- 單手補強優先：左手 Ride 與它的鄰居交替（中音↔Ride、落地↔Ride）。這次請錄影，並讓畫面拍得到左手 Ride（之前兩天都沒有左手 Ride 的影片）。
- 每段錄完看一下有沒有「⚠ 左/右手超過0.5秒沒有資料」；有的話那段後面不能用，重錄。
- 打 Tom 時留意線或鼓棒碰到小鼓：會產生假小鼓（力度 3～10），標記時已自動排除。

## 無線版操作
1. 韌體：`Firmware/Gloves_Left_L_UDP`（左）、`Firmware/Gloves_Right_R_UDP`（右）。燒錄前把同資料夾的 `wifi_secrets.example.h` 複製成 `wifi_secrets.h`，填手機熱點名稱與密碼（這個檔不進 git）。
2. 手機開熱點，電腦與兩隻手套都連同一個熱點。
3. 開 `1W_測前次_無線.bat` 或 `2W_蒐集這次_無線.bat` → 連接雙手（不用選 COM、不用填 IP）→ 鼓面歸零 → 開始。Windows 防火牆第一次跳出時請允許 Python 使用「私人網路」。
4. 每份 Raw 的 manifest 有 `transport`：每隻手收到、重複、補不回（skipped）的封包數，與手套 IP。
- 手套每 10 ms 送一行，和有線版同一行文字；每個 UDP 封包同時帶最近 3 行，掉一個封包不會少資料。
- 電腦每秒廣播 `HG_HELLO`（port 8889），手套聽到後改用單播送到這台電腦（port 8888）。
- 時間用手套自己的 10 ms 時鐘排；時間永遠不晚於實際收到的時刻（即時判斷不會偷看未來）。
- USB 線接著時，手套也同時從 COM 輸出，有線程式照樣能用。
- 韌體還沒在手套上實測過；第一次用請先錄一段看 manifest 的 skipped 與 hand_silent_periods。
