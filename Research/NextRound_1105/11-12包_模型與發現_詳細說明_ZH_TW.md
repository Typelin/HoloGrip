## 1. 名詞

| 名詞 | 意思 |

| 前測 | 照固定順序打的考試：小鼓左 10、右 10 開局，之後每顆鼓左 20、右 20。前測一律不進訓練。 |

| 鼓 | yaw | pitch |
|---|---:|---:|

| 中音 | −45 | +10 |

## 5. 11/10 的新發現

1. **對打的手勢和連打不同。**
   人員3 左手高音與中音，連打時 yaw 差 7°，LHM 對打時差 23°（中音跑到 −45°）。
   LHM 進訓練後，他前測的左手高音變差（14:52 12/12→2/12、15:37 9/20→3/20，都判成中音）。所以 LHM 不進訓練。
2. **連打的資料比對打有用（研究用假設，不出貨）。**
   把他 15:37 的通鼓前測當成訓練資料，他四份沒 MIDI 的前測 640→683（+43，反打 223→248），14:52 151→153、15:08 287→291。
   左手高音仍是 8～9/20，所以那一格不是資料量的問題。設定檔 `make_rounds_whatif.py`。
3. **同一顆鼓的手勢會跟著前一顆鼓改變。**
   人員3 右手中音：正打 yaw −116、反打 −128；Ride：正打 −153、反打 −138。反打時兩顆只差 10°，中音整段被判成 Ride。
4. **反打的錯，位置先驗有份，但關掉它別處會退步。** 13:44 關掉 225→255；13:36 正打 281→278。沒有兩邊都不退步的設定，所以沒改。
5. **歸零方向保護會誤觸發。** 13:39（沒開局）右手被轉 −60°；16:17 空氣反打右手被轉 −45°。關掉後 13:39 是 36→57。
   兩次都是開頭的幾下沒有被認成小鼓。
6. **錨點在空氣鼓會定錯。** 16:17 右手開局的小鼓被判成 Hi-Hat（分數 0.99），程式照「同一顆鼓、分數 ≥ 0.7」的規則錨到 Hi-Hat。真鼓資料裡錨點沒有錯過。
7. **純個人位置校正不夠。** 同一人用正打當校正、只看最近的位置去分反打：真鼓 68%，空氣 65%，比現場引擎差（`air_personal_1110.py`）。
8. **錄音內的角度漂移不大。** 歌曲裡同一顆鼓的 yaw 斜率多在每分鐘 ±4° 以內，3～5 分鐘累積 ±5～13°（`yaw_drift_1110.py`）。
   逐鼓校正在追的就是這個；關掉它，13:36 正打從 281 掉到 200。
9. **左手 Ride 是零和。** 10/27（人員1）與 11/06（人員2）的左手 Ride 位置衝突，模型一變，一邊變好另一邊就變差（0↔15、9↔1）。

## 6. 空氣鼓

沒有鼓、前方什麼都沒有，照前測順序在空中揮擊。三段都沒有答案，用每隻手的停頓切段＋標準順序估算。

| 錄音 | 現場模型 | e1 |
|---|---:|---:|
| 12:44 人員1（前 140 秒是一輪正打） | 約 223/298（75%） | 約 78% |
| 16:13 人員3 正打 | 274/299（91.6%） | 約 283/299（94.6%） |
| 16:17 人員3 反打 | 約 163/305（53%） | 未重算 |

看得到的事實：
- **偵測沒有問題。** 每段幾乎剛好抓到 20 下，打擊判斷只擋掉少數。
- **手停得比較高。** 沒有鼓面擋住。人員1 左手高音、中音的 pitch 是 21°（真鼓 7～13°），被判成 Crash。人員3 右手 Ride 61°（真鼓 28～32°）。
- **散佈比較大。** yaw 標準差到 18°。
- **右手小鼓像 Hi-Hat。** 人員3 兩段的右手小鼓各有一半以上被判成 Hi-Hat。
- **力道。** 人員1 空氣 3.5～4.5 g（真鼓 5～7 g）；人員3 空氣與真鼓相近（4～5 g）。
- **反打時錨點與歸零保護都出錯**（第 5 節第 5、6 點）。

還不能下的結論：空氣鼓的正式準確率。需要一份有順序紀錄（影片或題目標記）的空氣鼓錄音。

可以做的方向（都還沒做）：
1. 收有答案的空氣鼓資料，直接進訓練。照前測順序打，並錄影。
2. 空氣模式關掉歸零方向保護，錨點只接受小鼓。兩者都是這次空氣鼓實際出錯的地方。
3. 展演時讓打者即時聽到判出來的聲音，自己修正位置（延遲約 110 ms：等峰值後 80 ms＋處理 31 ms）。
4. 展演曲目照正常打法編：左手只負責小鼓、Hi-Hat、Crash、高音，中音、Ride、落地交給右手。人員3 的右手在真鼓與空氣正打都幾乎全對。

## 7. 11/17（人員3，09:00–11:00）建議怎麼收

1. 每一段都確認電子鼓在錄 MIDI；Ableton 專案固定 120 BPM。
2. 每一段開頭都先打小鼓（左 10、右 10）。
3. 補強改成**連打**：一顆鼓 20 下再換下一顆；每一輪換順序（正打、反打、跳著打）。不要兩鼓來回。
4. 前測存 `1_測前次`，補強與歌曲存 `2_蒐集這次`。
5. 想測空氣鼓：照前測順序，並錄影。
6. 歌曲照正常打法（左手不跨去打 Ride、落地），另外收一首「左手也打右邊通鼓」的對照。

## 9. 重現方法

資料（Raw、MIDI、模型、`out/`）不在 repo 裡。有資料的機器上，在 `Research/NextRound_1105/`：

```bash

python make_midi_R12.py            # Ableton MIDI 的訓練用副本（補速度、改名）
python make_rounds_1112.py         # 設定檔：R11 人員1、R12 人員3

python build_model.py --tag e1 --exclude "R9:ton1轉ton2 L,R12:高音轉中音 L,R10:中音轉Ride L"
python score.py --code 11-10的包 --model out/model_e1.joblib --tag full_e1
# 留一天：build_model.py --tag lodoe1_<天> --hold <天>（R4～R12 各一次）後
python score.py --code 11-10的包 --lodo --lodo-prefix lodoe1 --tag lodo_e1
python make_package_1112.py --model=out/model_e1.joblib --replace   # 建包＋凍結＋測試
```
