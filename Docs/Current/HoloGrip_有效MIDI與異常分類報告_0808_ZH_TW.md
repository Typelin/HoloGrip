# HoloGrip 有效 MIDI 與異常分類報告

更新日期：2026-08-08  
資料：0805 電子鼓 MIDI、100 Hz 手套 Raw CSV  
目前建議對外版本：**採樣窗口 ±90 ms（總長 180 ms）**

## 一、給會議的結論

本次用 1,820 筆實際 MIDI 鼓點，對照 74,592 列、100 Hz 的左右手手套 CSV。MIDI 對 CSV 目前使用 **+16,000 ms 候選偏移**。

以 ±90 ms 作為事件品質篩選後：

| 項目 | 筆數 |
|---|---:|
| MIDI 總事件 | 1,820 |
| 異常事件（從分母排除） | 705 |
| 有效 MIDI 候選分母 | **1,115** |
| 高信心單手 | **82** |
| 高信心雙手 | **18**（9 組，每組 2 筆） |
| 高信心合計 | **100** |
| 高信心占有效分母 | **9.0%** |

因此目前最準確的對外說法是：

> 以 ±90 ms 為品質篩選窗口，1,820 筆 MIDI 中有 705 筆先列為異常，剩下 1,115 筆作為有效候選分母；其中 82 筆是高信心單手、18 筆是高信心雙手，合計 100 筆，占有效候選分母 9.0%。這 100 筆仍需抽查影片；雙手資料還需要影片確認兩個 MIDI 各自的左、右手別。

「有效候選分母」不等於「已完成真值標記」。目前能直接作為第一版流程驗證的高信心資料是 100 筆，其他 1,015 筆仍是待人工判讀。

## 二、異常區的正式定義

異常區只使用以下兩種條件：

1. **同一鼓點在 20 ms 內重複**：任意兩筆相同 MIDI note 的時間差小於或等於 20 ms，兩筆都列為異常事件。這不是只看相鄰兩筆，避免中間插入另一個鼓點時漏抓。
2. **窗口內至少 3 個 MIDI**：以事件中心建立 ±90 ms 或 ±80 ms 窗口，窗口內若有 3 筆以上 MIDI，窗口內涉及的 MIDI 全部列為異常事件。

兩個不同鼓點、同一個 12 ms onset 群組、左右手活動線各只有一個明顯峰，**不會因為是雙手而列為異常**。只要不符合上面兩種異常條件，就可進入雙手乾淨候選判定。

異常導覽按鈕現在只走 `anomalyAreaIndices`，不再使用「所有待人工判讀區」，因此不會跳到雙手乾淨區。

## 三、±90 與 ±80 比較

兩者都使用相同的 MIDI、CSV、+16,000 ms 偏移、20 ms 同 note 稽核、12 ms onset 分組及 1.0g 活動峰門檻。

| 指標 | ±90 ms | ±80 ms |
|---|---:|---:|
| 窗口總長 | 180 ms | 160 ms |
| 異常事件 | 705 | 665 |
| 有效候選分母 | **1,115** | **1,155** |
| 高信心單手 | **82** | **84** |
| 其中左手候選 | 16 | 20 |
| 其中右手候選 | 66 | 64 |
| 高信心雙手組 | **9** | **7** |
| 高信心雙手 MIDI 筆數 | **18** | **14** |
| 高信心合計 | **100** | **98** |
| 占有效候選分母 | **9.0%** | **8.5%** |
| 待人工判讀 | 1,015 | 1,057 |

### 窗口建議

- **如果會議只能講一個數字：講 ±90 ms。** 目前頁面預設也是 ±90 ms，定義清楚且較保守。
- **如果分成資料稽核和模型輸入兩層：±90 ms 做品質篩選，±80 ms 做固定長度模型輸入。** 但報告中的分母必須註明使用哪一個窗口，不能把 ±90 的 1,115 和 ±80 的高信心數混在一起。
- ±80 ms 並沒有增加高信心資料：高信心合計是 98，比 ±90 的 100 少 2 筆。因此不能只因窗口較小就宣稱資料品質變好。

## 四、Hi-Hat 20 ms 快速重複

目前 20 ms 稽核結果：

| 指標 | 結果 |
|---|---:|
| 相同 MIDI note、20 ms 內的配對 | **153 對** |
| 涉及的唯一 MIDI 事件 | **291 筆** |
| 涉及的 note | **全部是 46（Hi-Hat）** |

153 對和 291 筆不是同一個概念：同一筆事件可能同時出現在多個快速重複配對中，所以唯一事件數會高於配對數。

這些事件目前應稱為「Hi-Hat 快速重複疑似異常」，不能直接宣稱 MIDI 檔案一定錯誤。可能性包括：

- 第一下是真的擊打，第二下是電子鼓模組的重複觸發。
- 演奏者在極短時間內真的完成快速連擊。
- 錄音或 MIDI 設定產生額外 note-on。

需要用影片和 WAV 在同一時間段逐組抽查，才能決定保留、合併或排除。

## 五、分類條件

### 高信心單手

一個 12 ms onset 群組只有一筆 MIDI，且符合：

- 不在異常條件中。
- 前後 MIDI 群組距離至少 `2 × 窗口半徑`，避免窗口互相污染。
- CSV 對齊窗口中的手套活動峰至少 `1.0g`。
- 左右活動峰推估出的主手信心至少 90%。

±90 ms 結果為左手候選 16、右手候選 66。這是 CSV 推估的手別，不是 MIDI 原生手別真值。

### 高信心雙手

一個 12 ms onset 群組正好有兩筆 MIDI，兩筆 note 不同，並且在同一個窗口中：

- 左手有且只有一個局部活動峰。
- 右手有且只有一個局部活動峰。
- 每個活動峰至少 `1.0g`。
- 同一手的兩個峰至少相距 40 ms，避免把同一個尖峰重複算兩次。
- 事件本身不在異常區，且前後群組不使窗口重疊。

MIDI 沒有左手／右手欄位，所以 18 筆只能先稱為高信心雙手候選。影片確認後，才能把兩個 MIDI note 分配成左手或右手。

## 六、資料可以做到什麼程度

目前可以做：

- 以 MIDI 提供「何時打、打哪個鼓點」。
- 以 CSV 提供左右手活動時間序列與活動峰。
- 自動排除明確的 20 ms 同鼓點重複與窗口內 3 點以上密集區。
- 產生高信心單手與雙手候選。
- 對 Hi-Hat 快速重複事件建立影片／WAV 人工稽核清單。
- 用高信心候選跑第一版資料切窗、特徵處理與模型流程驗證。

目前不能直接宣稱：

- MIDI 已經知道每一筆是左手或右手。
- 1,115 筆有效候選都已能直接訓練。
- 100 筆已經是影片確認後的正式真值。
- 單一歌曲即可證明跨歌曲、跨演奏者泛化能力。

100 筆適合驗證整條流程能否跑通，資料量仍不足以證明正式模型可靠；尤其需要看 7 個鼓點的分布與左手樣本是否足夠。

## 八、剩餘風險

1. `+16,000 ms` 仍是 MIDI 到 CSV 的候選偏移，需用影片與 WAV 在開頭、中段、結尾抽查。
2. Hi-Hat 的 153 對必須用影片／WAV 判斷是真快速連擊還是重複觸發。
3. 雙手 18 筆尚未由影片逐筆分配左、右手。
4. 高信心門檻與 `1.0g` 活動峰是目前第一版可解釋規則，之後可用人工確認結果做敏感度分析。
5. 本報告的有效分母是「排除規則異常後的候選分母」，不是最終訓練真值數量。
