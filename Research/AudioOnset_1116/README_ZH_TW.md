# 影片聲音解析（11/16）

從 11/12 手機影片 `20261112_113843.mp4`（5 分 7 秒，48 kHz）抽出聲音，跟同一段歌曲1 的電子鼓 MIDI 比對。
程式：`audio_1112.py`（輸入唯讀；輸出在 `out/`）。工具：`librosa 1.0.1`、`soundfile`、`imageio-ffmpeg`（自帶 ffmpeg，不改系統）。

## 結果

| 項目 | 結果 |
|---|---|
| 聲音↔MIDI 對齊 | 刻度 1.0000、對齊率 93.3% |
| 抓到打擊（7 鼓事件） | 91.4%（30 ms 內） |
| 多抓的聲音 | 225 個中 170 個是大鼓（MIDI 36，7 鼓答案裡沒有）；把大鼓算進去，準確率 94.0% |
| 時間分散（減掉固定偏移後，相對 MIDI） | 聲音 std 7.5 ms（中位 4.6 ms）；手套峰值 std 13.6 ms（中位 10.2 ms） |
| 只聽聲音分鼓種（單獨音 518 下，5 段時間交叉驗證） | **96.9%**（猜最多那類只有 36.5%）；鈸 vs 鼓 99.6% |

逐鼓：小鼓 170/174、Hi-Hat 186/189、Crash 40/42、高音 34/34、中音 13/14、Ride 34/38（4 下→Hi-Hat）、落地 25/27（2 下→小鼓）。

## 解讀
- 影片錄得到電子鼓音箱的聲音，所以三顆通鼓靠音高分得開，聲音可以當答案。
- 聲音的時間比手套峰值更集中，可以當打擊時間的參考。
- 只有相對時間：影片和手套沒有共同時鐘，「手套峰值比真正打擊早或晚多少」的固定差值量不到。要量延遲，需要現場同時錄到聲音和手套（例如筆電麥克風跟手套用同一個時鐘）。

## 限制
- 訓練和測試都是同一首歌、同一天、同一個房間（用時間分段避免相鄰打擊混用）。換房間、換鼓組音色、戴耳機打（沒有音箱聲）都還沒驗證。
- 兩下同時打（和弦）沒有拿來分類，只用單獨音。

## 鼓聲單音檔（播放用，`cut_samples_1112.py`）

從同一支影片切出每顆鼓的單音 wav（48 kHz、單聲道、16-bit、峰值 −1 dBFS、尾端 40% 淡出），輸出到 `samples_1112/`，`index.json` 記錄每個檔的 MIDI 音符、力道、長度與影片時間。
挑法：用歌曲1 的 MIDI（含大鼓 36）找「後面最久沒有下一個音」的打擊，取其中最用力的。

| 鼓 | 檔案 | 長度 |
|---|---|---|
| 大鼓 | `kick_1.wav`、`kick_2.wav` | 560、492 ms |
| 小鼓 | `snare_1.wav`、`snare_2.wav` | 590、590 ms |
| Hi-Hat | `hihat_1.wav` | 400 ms |
| Crash | `crash_1.wav` | 172 ms（被下一個音切斷，餘音不完整） |
| 高音 | `tom_high_1.wav` | 563 ms（頻譜上有前面鈸的餘音混入） |
| 中音 | `tom_mid_1.wav` | 360 ms |
| Ride | `ride_1.wav` | 393 ms |
| 落地 | `tom_floor_1.wav` | 590 ms |

限制：歌曲裡的音一個接一個，鈸的餘音一定被切斷或混到別的聲音；手機麥克風也錄到房間聲。這批只適合當原型。
要正式播放用的乾淨音檔，最簡單的做法是現場請鼓手每顆鼓單獨打 3～5 下、每下間隔 3 秒，手機靠近電子鼓音箱錄影；用同一套程式即可自動切出。

音檔與抽出的整段聲音（`audio/`、`samples_1112/`）是由現場影片產生的資料，不進 git。
