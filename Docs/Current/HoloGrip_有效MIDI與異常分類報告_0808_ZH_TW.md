# HoloGrip 有效 MIDI 與異常分類報告

更新日期：2026-08-08  
資料：0805 電子鼓 MIDI、100 Hz 手套 Raw CSV  
目前建議模型資料版本：**採樣窗口 ±80 ms（總長 160 ms）**；±90 ms 保留作保守稽核比較

## 零、先回答：先前約 100 筆是統計 bug

先前看到的「約 100 筆可用」不是 MIDI 真實只有約 100 筆，而是稽核程式的統計 bug，不能拿來當資料量結論。

### Bug 根因

1. 舊版計算手套活動峰時，直接使用 MIDI 時間查 CSV，漏掉已確認的 **MIDI → CSV `+16,000 ms` 偏移**；因此查到錯誤時間區段。
2. 舊版手別信心曾固定用 `±120 ms` 計算，沒有跟目前比較中的 `±80 ms`／`±90 ms` 同步。
3. 這兩個問題會讓真正對齊的活動峰沒有被算進來，造成高信心數量被低估；它不是資料真的只剩 100 筆。

### 修正與驗證

- 修正基準 commit：`d752bdc Correct aligned window quality counts`
- 修正後每次以目前半徑重新計算 CSV 對齊時間、左右峰值與手別信心。
- 重新執行稽核腳本後，輸出仍得到：±80 ms 高信心 **342 筆**、±90 ms 高信心 **325 筆**。
- 因此目前應以 **342／325 筆高信心候選**作為分析結果，不再使用先前約 100 筆的數字。

本報告中的「高信心」仍是規則產生的候選，不等於影片已逐筆確認的最終真值；雙手事件尤其需要影片確認左右手分配。

## 一、給會議的結論

本次用 1,820 筆實際 MIDI 鼓點，對照 74,592 列、100 Hz 的左右手手套 CSV。MIDI 對 CSV 目前使用 **+16,000 ms 候選偏移**。

以 ±90 ms 作為保守事件品質篩選後：

| 項目 | 筆數 |
|---|---:|
| MIDI 總事件 | 1,820 |
| 異常事件（從分母排除） | 705 |
| 有效 MIDI 候選分母 | **1,115** |
| 高信心單手 | **241** |
| 高信心雙手 | **84**（42 組，每組 2 筆） |
| 高信心合計 | **325** |
| 高信心占有效分母 | **29.1%** |
| 高信心占全部 1,820 筆 MIDI | **17.9%** |

因此目前最準確的對外說法是：

> 以 ±90 ms 為保守品質篩選窗口，1,820 筆 MIDI 中有 705 筆先列為異常，剩下 1,115 筆作為有效候選分母；其中 241 筆是高信心單手、84 筆是高信心雙手，合計 325 筆，占有效候選分母 29.1%。這 325 筆仍需抽查影片；雙手資料還需要影片確認兩個 MIDI 各自的左、右手別。

「有效候選分母」不等於「已完成真值標記」。目前 325 筆是高信心候選，另外 790 筆仍是有效但待人工判讀；另有 705 筆先列為異常。

## 二、異常區的正式定義

異常區只使用以下兩種條件：

1. **同一鼓點在 20 ms 內重複**：任意兩筆相同 MIDI note 的時間差小於或等於 20 ms，兩筆都列為異常事件。這不是只看相鄰兩筆，避免中間插入另一個鼓點時漏抓。
2. **窗口內至少 3 個 MIDI**：以事件中心建立 ±90 ms 或 ±80 ms 窗口，窗口內若有 3 筆以上 MIDI，窗口內涉及的 MIDI 全部列為異常事件。

兩個不同鼓點、同一個 12 ms onset 群組、左右手活動線各只有一個明顯峰，**不會因為是雙手而列為異常**。只要不符合上面兩種異常條件，就可進入雙手乾淨候選判定。

異常導覽按鈕現在只走 `anomalyAreaIndices`，不再使用「所有待人工判讀區」，因此不會跳到雙手乾淨區。

## 三、±90 與 ±80 比較

兩者都使用相同的 MIDI、CSV、+16,000 ms 偏移、20 ms 同 note 稽核、12 ms onset 分組及 1.0g 活動峰門檻。

| 指標 | ±90 ms | ±80 ms |
|---|---:|---:|
| 窗口總長 | 180 ms | 160 ms |
| 異常事件 | 705 | 665 |
| 有效候選分母 | **1,115** | **1,155** |
| 高信心單手 | **241** | **256** |
| 其中左手候選 | 32 | 42 |
| 其中右手候選 | 209 | 214 |
| 高信心雙手組 | **42** | **43** |
| 高信心雙手 MIDI 筆數 | **84** | **86** |
| 高信心合計 | **325** | **342** |
| 占有效候選分母 | **29.1%** | **29.6%** |
| 高信心占全部 1,820 筆 MIDI | **17.9%** | **18.8%** |
| 待人工判讀 | 790 | 813 |

### 窗口建議

- **如果會議只能講一個訓練資料數字：講 ±80 ms。** 目前它保留 342 筆高信心候選，略高於 ±90 ms 的 325 筆。
- **如果分成資料稽核和模型輸入兩層：±90 ms 做保守抽查，±80 ms 做固定長度模型輸入。** 兩個窗口的分母與百分比必須分開報告。
- ±80 ms 比 ±90 ms 多 17 筆高信心候選，但也應抽查這些新增的邊界事件，不能只看數量。

### CSV 對應量的正確說法

- Raw CSV 共 **74,592 列**：左手 37,296 列、右手 37,296 列。
- 每個高信心 MIDI 點對應一個包含左右手訊號的固定時間窗口；同一筆 CSV 可能落在相鄰 MIDI 窗口，不應把 `342 × 窗口列數` 說成 342 份完全獨立資料。
- 程式目前先把 Raw CSV 整理成 **10 ms 特徵格**，再依 MIDI 對齊時間切窗。±80 ms 是 160 ms 區間，±90 ms 是 180 ms 區間；實際格數會受 MIDI 小數時間與歌曲邊界影響，模型輸入階段仍需統一重採樣／補齊成固定尺寸。

## 五、資料數量與訓練品質判斷

目前建議採用 **±80 ms 作為第一版模型固定輸入窗口**，理由不是只追求數量，而是它同時有三個優勢：

1. 高信心候選多 17 筆（342 對 325），增加約 5.2%。
2. 高信心占有效候選分母只高 0.5 個百分點（29.6% 對 29.1%），品質代理指標沒有下降。
3. 窗口較短，較不容易把前一個或下一個鼓點的活動吸進同一筆訓練資料；這符合目前密集區的主要風險。

因此決策為：

- **模型輸入：±80 ms，總長 160 ms。**
- **稽核與邊界抽查：±90 ms，總長 180 ms。** 用來檢查±80 ms兩側是否有被截掉的重要活動，不把±90的額外背景直接混進模型。
- 先人工確認±80 ms的342筆，至少優先確認43組雙手與153對Hi-Hat快速重複附近事件，再決定哪些可以升級為正式訓練真值。

品質限制必須明說：342筆只足夠驗證資料切窗、標記格式、特徵處理與第一版模型流程，還不足以證明正式模型能穩定泛化。樣本也明顯不平衡，Hi-Hat有180筆，但高音Tom只有2筆、中音Tom只有3筆；單手左手只有42筆，影片確認後可由雙手資料補充，但目前不能假設補充一定成立。

## 六、Hi-Hat 20 ms 快速重複

目前 20 ms 稽核結果：

| 指標 | 結果 |
|---|---:|
| 相同 MIDI note、20 ms 內的配對 | **153 對** |
| 涉及的唯一 MIDI 事件 | **291 筆** |
| 涉及的 note | **全部是 46（Hi-Hat）** |

153 對和 291 筆不是同一個概念：同一筆事件可能同時出現在多個快速重複配對中，所以唯一事件數會高於配對數。

這些事件目前應稱為「Hi-Hat 快速重複疑似異常」，不能直接宣稱 MIDI 檔案一定錯誤。可能性包括：

- 第一下是真的擊打，第二下是電子鼓模組的重複觸發。
- 演奏者在極短時間內真的完成快速連擊。
- 錄音或 MIDI 設定產生額外 note-on。

需要用影片和 WAV 在同一時間段逐組抽查，才能決定保留、合併或排除。

## 七、分類條件

### 高信心單手

一個 12 ms onset 群組只有一筆 MIDI，且符合：

- 不在異常條件中。
- 前後 MIDI 群組距離至少 `2 × 窗口半徑`，避免窗口互相污染。
- CSV 對齊窗口中的手套活動峰至少 `1.0g`。
- 左右活動峰推估出的主手信心至少 90%。

±90 ms 結果為左手候選 32、右手候選 209。這是 CSV 推估的手別，不是 MIDI 原生手別真值。

### 高信心雙手

一個 12 ms onset 群組正好有兩筆 MIDI，兩筆 note 不同，並且在同一個窗口中：

- 左手有且只有一個局部活動峰。
- 右手有且只有一個局部活動峰。
- 每個活動峰至少 `1.0g`。
- 同一手的兩個峰至少相距 40 ms，避免把同一個尖峰重複算兩次。
- 事件本身不在異常區，且前後群組不使窗口重疊。

MIDI 沒有左手／右手欄位，所以 84 筆只能先稱為高信心雙手候選。影片確認後，才能把兩個 MIDI note 分配成左手或右手。

## 八、資料可以做到什麼程度

目前可以做：

- 以 MIDI 提供「何時打、打哪個鼓點」。
- 以 CSV 提供左右手活動時間序列與活動峰。
- 自動排除明確的 20 ms 同鼓點重複與窗口內 3 點以上密集區。
- 產生高信心單手與雙手候選。
- 對 Hi-Hat 快速重複事件建立影片／WAV 人工稽核清單。
- 用高信心候選跑第一版資料切窗、特徵處理與模型流程驗證。

目前不能直接宣稱：

- MIDI 已經知道每一筆是左手或右手。
- 1,115 筆有效候選都已能直接訓練。
- 325～342 筆已經是影片確認前的高信心候選，不是正式真值。
- 單一歌曲即可證明跨歌曲、跨演奏者泛化能力。

325～342 筆適合驗證整條流程能否跑通，資料量仍不足以證明正式模型可靠；尤其需要看 7 個鼓點的分布與左手樣本是否足夠。

## 十、剩餘風險

1. `+16,000 ms` 仍是 MIDI 到 CSV 的候選偏移，需用影片與 WAV 在開頭、中段、結尾抽查。
2. Hi-Hat 的 153 對必須用影片／WAV 判斷是真快速連擊還是重複觸發。
3. 雙手 84 筆尚未由影片逐筆分配左、右手。
4. 高信心門檻與 `1.0g` 活動峰是目前第一版可解釋規則，之後可用人工確認結果做敏感度分析。
5. 本報告的有效分母是「排除規則異常後的候選分母」，不是最終訓練真值數量。
